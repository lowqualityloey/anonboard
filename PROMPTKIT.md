## 1. Project Overview & Domain
- **Project Name**: AnonBoard
- **Domain / Purpose**: Lightweight anonymous discussion board where users browse boards, create threads, and reply without accounts.
- **Primary Users**: Anonymous community members, students, board administrators (moderation).

---

## 2. Active Technology Stack
- **Language & Runtime**: TypeScript (Strict), Node.js v24
- **Meta-Framework & Routing**: TanStack Start (Vite + Nitro), TanStack Router (file-based, type-safe)
- **Frontend Framework**: React 19
- **Styling & Design System**: Tailwind CSS v4 with custom `@theme` semantic design tokens (`DESIGN.md`)
- **State & Data Fetching**: TanStack Query (polling + cache invalidation), Route Loaders
- **Backend & Database**: Prisma ORM, Supabase Postgres (pooled port 6543 at runtime, direct port 5432 for migrations)
- **Validation**: Zod
- **Admin Auth**: Environment password (`ADMIN_PASSWORD`) + signed HttpOnly cookie session (`SESSION_SECRET`)
- **Hosting / Deployment Target**: Vercel (Serverless)

## 7. Non-Negotiable Architecture Rules & Guardrails
- [ ] **Strict Route Loader Data Fetching**: Page-level data fetching must happen in route loaders, never in unstructured `useEffect` blocks.
- [ ] **Strict Server Function Mutations**: Mutations must use TanStack Start `createServerFn` with Zod validation, followed by explicit query or router invalidation.
- [ ] **Prisma Server Isolation**: Prisma client singleton (`src/server/db.ts`) must never be imported into client components or client bundles.
- [ ] **Serverless Connection Pooling**: Always configure pooled database connection URL (`?pgbouncer=true&connection_limit=1`) on Vercel runtime.
- [ ] **Deterministic Anonymous Tag Generation**: Anonymous tags must follow `Anon ` + `hash(anon_id + threadId).slice(0, 4)` so identity is consistent per thread but disconnected across threads.
- [ ] **Semantic Design Tokens First**: Use semantic tokens (`bg-surface`, `text-text`, `bg-accent`) from `DESIGN.md`, never raw palette values (`bg-gray-900`).
- [ ] **Soft-Delete Enforcement**: Thread and post deletions must be soft (`isDeleted = true`) by default.
- [ ] **Anti-Slop & Structured Scannable Output**: Format status updates, plans, and diffs in structured scannable markdown tables and checklists.
- [ ] **Absolute Secret Hygiene**: Never output, commit, or request raw database credentials or session secrets in chat; enforce `.env.example` templates.
- [ ] **Standardized Human Action Callouts**: When halting for human confirmation, end responses with a `> [!IMPORTANT]` block titled `### 🛑 Action Required From You:`.
- [ ] **Strict Milestone Git Boundaries**: Never start a new milestone or major task phase with an uncommitted or dirty working tree. Upon completing a milestone, run test verification, prompt for or execute atomic staging (`pk:commit`), update `docs/STATE.md`, and obtain human confirmation with `> [!IMPORTANT]` before proceeding.
